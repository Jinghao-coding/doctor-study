当前站点已经覆盖 AI Infra 面试的主干：模型基础、GPU/CUDA、LLM 推理、分布式训练、Kubernetes、调度、集群管理、性能建模、系统设计和计算机基础。主要遗漏不是单个算法，而是生产化闭环：数据和模型资产如何进入平台、服务如何观测和守 SLO、容量成本如何规划、发布安全和事故复盘如何闭环。

数据、模型与制品链路

进阶★☆☆⏱ 18 min

一句话结论

AI Infra 的生产链路不是“代码提交后跑一个 Job”，而是把数据集、训练配置、checkpoint、模型权重、镜像、推理配置和评测结果都变成可追踪、可回滚、可审计的制品。面试回答要强调版本、血缘、准入和回滚四件事。

核心概念

制品解决什么问题关键元数据
Dataset训练、评测和回放的数据来源版本、schema、样本量、来源、权限、质量报告
Training Config复现实验和训练任务代码 commit、镜像、超参、并行策略、资源规格
Checkpoint训练恢复、模型导出和回滚step、metric、optimizer state、并行切分方式、存储路径
Model Artifact推理部署的模型权重和 tokenizerbase model、finetune 方法、精度、量化方式、签名
Container Image运行环境一致性digest、CUDA/driver 兼容、依赖版本、安全扫描结果
Serving Config推理服务行为engine、tensor parallel、max tokens、batch 策略、限流策略
Evaluation Report模型准入依据benchmark、线上回放、红线 case、回归结果、审批人

系统链路

01
数据进入
数据集版本、schema、权限、质量检查
02
训练提交
代码、镜像、配置、资源和数据版本绑定
03
运行产出
checkpoint、日志、metrics、profile、失败事件沉淀
04
模型注册
权重、tokenizer、配置、评测报告和血缘写入 registry
05
部署准入
评测达标、安全扫描、容量预估、灰度策略确认
06
线上回滚
按模型版本、镜像 digest 和 serving config 一起回滚

关键机制

血缘不是文档，是平台状态

模型注册时必须能回答：这个模型来自哪个 base model、哪个数据集版本、哪次训练任务、哪个 checkpoint、哪份评测报告、哪个镜像和哪份 serving config。否则线上出问题时只能靠人工猜。

Checkpoint 与 Model Artifact 的边界

Checkpoint 服务训练恢复，通常包含 optimizer state、scheduler state、随机数状态和并行切分信息；Model Artifact 服务推理部署，通常只保留权重、tokenizer、模型结构、量化参数和推理配置。两者不能混为一谈。

镜像用 tag 不够，要用 digest

生产发布不能只记录 latest 或普通 tag，因为 tag 可变。准入、回滚和审计应记录 image digest、构建流水线、依赖 SBOM 和安全扫描结果。

常见误区

误区正确说法
只要保存模型权重就能复现还需要数据版本、代码 commit、镜像、配置、随机种子和评测结果
checkpoint 就是线上模型checkpoint 偏训练恢复，线上模型要经过导出、转换、量化、评测和注册
模型 registry 只是文件目录registry 应保存元数据、血缘、权限、准入状态和版本生命周期
回滚只回滚权重需要一起回滚镜像、engine 参数、tokenizer、prompt/config 和路由策略
数据质量是算法问题数据 schema、缺失、重复、脏样本、权限和合规都是平台问题

关联模块

  • 分布式训练平台：训练任务产出 checkpoint 和模型制品。
  • LLM 推理系统：模型制品进入 serving engine 后变成线上服务。
  • Kubernetes 核心：镜像、ConfigMap、Secret、Service 和 Deployment 承载运行环境。
  • 系统设计题：资产血缘和回滚是综合设计题里的加分点。

可观测性、SLO 与容量成本

精通★☆☆⏱ 20 min

一句话结论

AI Infra 的可观测性要把业务指标、模型指标、系统指标和调度指标连起来；容量规划要从 SLO 反推 GPU、显存、网络、存储和队列余量。面试不要只说 Prometheus，要说指标分层、告警归因、容量模型和成本权衡。

指标分层

层级训练场景推理场景调度 / 平台场景
业务指标任务成功率、训练完成时间、有效吞吐QPS、成功率、TTFT、TPOT、P95/P99提交成功率、准入延迟、排队时长
模型指标loss、gradient norm、tokens/s、MFU输出 token/s、cache hit、acceptance rate不直接看模型质量，但要关联模型大小和资源需求
GPU 指标GPU-Util、SM Active、HBM、显存、ECC、功耗HBM、KV cache、batch size、kernel timeline卡健康、碎片率、MIG/MPS 归因
网络指标NCCL 带宽、重传、RDMA error、AllReduce 时间P/D 分离 KV 传输、跨节点延迟节点拓扑、交换机拥塞、机架放置
存储指标数据加载吞吐、checkpoint 时间、元数据延迟权重加载、模型分发、日志写入PVC attach、对象存储吞吐、缓存命中
控制面指标Operator reconcile、API error、队列 depth发布状态、endpoint 健康scheduler latency、binding error、quota ledger

SLO 设计

推理 SLO

常见目标是可用性、错误率、TTFT、TPOT、P99、吞吐和成本。交互式服务通常优先保护 TTFT 和 TPOT；离线批处理更关注吞吐和单位成本。

训练 SLO

训练不一定有请求级延迟，但有任务级 SLO：排队时间、启动时间、失败恢复时间、checkpoint 保存时间、tokens/s、MFU、任务完成率和资源浪费率。

告警要避免只看单点指标

GPU-Util 低不能直接说明 GPU 问题，可能是 DataLoader、H2D、NCCL、存储、调度队列或应用同步点。告警应该带上上下文指标，方便直接归因。

05

06
持续校准
用线上 metrics 和 profile 修正容量模型
问题估算方法风险
推理需要多少 GPU单卡 tokens/s、batch 策略、TTFT/TPOT SLO、峰值 QPS长 prompt 和 KV cache 可能比权重更先打满显存
训练队列需要多少 GPU到达率、平均训练时长、资源规格、目标排队时间Gang 作业和拓扑约束导致碎片
该买哪类 GPU模型大小、精度、显存容量、HBM 带宽、互联、功耗只看 TFLOPS 会忽略 memory-bound 和通信瓶颈
成本如何衡量GPU 小时、tokens/J、tokens/$、利用率、失败重跑率平均利用率高不代表 P99 和用户体验好

发布、安全与事故闭环

精通★☆☆⏱ 18 min

一句话结论

AI Infra 的生产发布不是把模型服务重启一下，而是让模型、镜像、配置、路由、权限和观测一起受控变更。面试回答要把灰度、回滚、安全边界和事故复盘讲成一条闭环。

发布链路

01
变更准备
模型版本、镜像 digest、serving config、资源预算、评测报告
02
准入检查
离线评测、回放、性能压测、安全扫描、容量评估
03
灰度发布
小流量、指定租户、影子流量或 canary endpoint
04
实时观测
错误率、TTFT、TPOT、P99、GPU 显存、KV cache、日志
05
自动回滚
指标越线、健康检查失败、资源异常或人工确认
06
复盘沉淀
根因、时间线、检测缺口、修复项、预防项

发布策略

策略适合场景风险点
Rolling Update无状态 API、普通控制面服务版本混跑期间要兼容旧配置
Blue-Green回滚要求高、切流明确成本更高，需要双份容量
Canary大模型推理服务、调度器策略、Operator 变更指标窗口太短会误判，太长会扩大影响
Shadow Traffic新模型或新推理引擎验证影子流量不能影响线上，且要处理隐私数据
Feature Flag调度策略、限流、缓存策略flag 爆炸会增加排障复杂度

安全边界

权限隔离

训练和推理平台应按租户、namespace、service account、RBAC、quota 和资源池隔离。用户不能直接拿集群级权限，平台控制器也应最小权限运行。

Secret 与数据权限

模型下载 token、对象存储 key、数据库密码、私有数据集权限都不能写进镜像或普通 ConfigMap。Secret 要配合访问审计、轮转和最小可见范围。

供应链安全

镜像要记录 digest、构建来源、依赖版本和扫描结果；模型制品也要记录来源、license、评测和准入状态。不要让未审核镜像或未知来源权重直接进入生产 GPU 池。

事故闭环

阶段要回答的问题证据
发现谁发现、哪个 SLO 越线、影响范围多大告警、dashboard、用户反馈
定位是模型、引擎、GPU、网络、存储、调度还是控制面metrics、logs、trace、events、profile
止血限流、回滚、摘节点、切路由、扩容还是禁用策略发布记录、路由记录、变更单
修复根因修掉了吗，是否有回归测试MR、测试、压测、回放
预防哪个检测缺口导致没有提前发现新告警、准入规则、演练、runbook

常见误区

误区正确说法
模型发布只要 A/B 看效果还要看性能、容量、安全、回滚和观测
回滚就是切回旧权重需要一起回滚镜像、tokenizer、config、engine 参数和路由
训练平台不用考虑安全数据集、checkpoint、日志和 shell 权限都可能泄露敏感信息
调度器改动可以直接全量调度策略影响全局资源，应先影子评估、小流量或按队列灰度
事故复盘只是写文档复盘要产生检测、准入、自动化和架构改进项

关联模块

  • Kubernetes 核心：RBAC、Admission、Secret、Deployment 和 Operator 发布机制。
  • LLM 推理系统：推理服务灰度、路由和 SLO 指标。
  • GPU 集群管理：资源池隔离、配额、节点健康和故障域。
  • AI Agent：工具权限、数据访问边界和审计也属于生产治理。
