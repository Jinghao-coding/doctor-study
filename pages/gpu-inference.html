LLM 推理流程

四阶段流程

  1. 模型加载：权重从存储（磁盘/网络）加载到 GPU 显存。大模型可能需要几十秒到几分钟
  2. Prefill（预填充，计算密集）：一次性处理整个 prompt，并行计算所有 token 的 attention，生成初始 KV 缓存。延迟主要取决于 prompt 长度和模型大小
  3. Decode（解码，内存密集）：自回归逐 token 生成。每步只计算一个新 token 的 attention，但需要读取全量 KV 缓存。带宽瓶颈，GPU 计算单元大量空闲
  4. 返回结果：流式输出或一次性返回

关键性能指标

指标含义影响因素

KV 缓存与 Attention 优化

KV 缓存机制

自回归解码时，每步需要之前所有 token 的 Key 和 Value 向量。如果每步重新计算，代价是 O(n²)。KV 缓存把之前算过的 K/V 存下来，每步只计算新 token 的 K/V 并追加。

KV 缓存大小 = 2 × num_layers × num_heads × head_dim × seq_len × dtype_size

以 LLaMA-70B 为例：2 × 80 × 8 × 128 × 4096 × 2（FP16）≈ 10.7GB（单个请求）。

为什么 KV 缓存是瓶颈？GPU 显存有限（80GB），模型权重占 140GB（FP16）需要张量并行到多卡。剩余显存被 KV 缓存瓜分，决定了能同时服务多少请求。

PagedAttention（vLLM）

传统 KV 缓存预分配连续内存，最大长度固定，短请求浪费严重。PagedAttention 借鉴操作系统虚拟内存的分页思想：

  • 把 KV 缓存切成固定大小的 block（如 16 token 一块）
  • 用 block table 维护逻辑到物理的映射
  • 按需分配，请求结束释放，消除内部碎片
  • 支持 copy-on-write，多个 beam 可共享公共前缀

Attention 变体

变体KV Head 数KV 缓存大小代表模型
MHA（Multi-Head Attention）= Query Head 数最大GPT-3, LLaMA-1

MQA（Multi-Query Attention）1最小Falcon, StarCoder

GQA 是实际部署的主流选择——在质量和效率之间取得平衡。

FlashAttention

标准 attention 的显存占用 O(N²)，FlashAttention 通过 tiling（分块计算）+ 重计算（不存中间 softmax 矩阵）将显存降到 O(N)，同时利用 GPU SRAM 提速。核心思想：用计算换显存，避免 HBM 的反复读写。

Q: MIG 和 MPS 的本质区别？

MIG 是硬件级切分——GPU 被物理切成若干独立实例，每个实例有自己的 SM、显存控制器和缓存，互相完全隔离，类似物理分区。MPS 是软件级复用——多个进程共享同一个 GPU 上下文，kernel 可以并行执行在不同 SM 上，但共享显存和缓存，有干扰风险。MIG 安全但粒度粗（A100 最多 7 个实例），MPS 灵活但需要干扰控制。

Q: CUDA VMM 的虚拟内存超配原理？

类似操作系统的虚拟内存：用 cuMemAddressReserve 分配大块虚拟地址（如 122GB），再用 cuMemMap 按需映射物理页。物理显存只有 40GB，但虚拟地址空间 122GB。应用看到连续大内存，实际物理页按需分配和回收。

推理优化技术

常见优化手段

技术原理效果
连续批处理（Continuous Batching）请求完成立即释放位置，新请求加入，不等整批结束吞吐提升 2-5×
张量并行（Tensor Parallelism）单层的矩阵乘法切分到多卡并行计算降低延迟，需 NVLink
流水线并行（Pipeline Parallelism）不同层放不同卡，请求依次流过支持更大模型
投机解码（Speculative Decoding）小模型快速生成候选 token，大模型验证延迟降低 2-3×
量化（INT8/FP8/INT4）降低权重和激活精度显存减半，速度提升
前缀缓存（Prefix Caching）共享前缀的请求复用 KV 缓存减少重复计算
CUDA Graph录制 kernel 调用序列为图，一次提交减少 CPU-GPU 启动开销
Q: 连续批处理和传统静态批处理的区别？

静态批处理：一批请求同时开始，最慢的请求完成后整批释放。短请求等长请求，GPU 空转。连续批处理（iteration-level scheduling）：每个 decode step 结束后检查，已完成的请求释放位置，等待的请求立即加入。GPU 始终满载。vLLM、TensorRT-LLM 都采用连续批处理。

Q: 投机解码为什么能加速？不是算了两次吗？

关键在于 decode 阶段是内存密集型——GPU 算力大量闲置。小模型（draft model）快速自回归生成 K 个候选 token，大模型（target model）一次性并行验证这 K 个 token（相当于做一次 prefill）。验证比逐个解码快，因为并行利用了算力。如果候选全部接受，等价于一次 forward 生成了 K 个 token。
