## 分布式训练在 AI Infra 中的定位

分布式训练解决的核心问题是：**单卡放不下、单卡训不快**。当模型和数据规模超过一张 GPU 的算力和显存时，就要用并行策略把计算和参数切分到多卡多机，并通过高效通信把它们重新粘合起来。

面试考分布式训练，本质是确认：你是否理解四种并行（数据/张量/流水线/专家）各自切什么、通信什么，以及显存和通信之间的权衡。

<div class="card card-d">
<h3>一句话定位</h3>
<p>分布式训练 = <strong>切分（并行策略） + 通信（NCCL 集合通信） + 显存优化（ZeRO/FSDP）</strong>。每种并行都是在"省显存、提算力、降通信"三者之间做取舍。</p>
</div>

## 与其他模块的关系

| 关联模块 | 关系 | 关键连接点 |
|---|---|---|
| GPU 硬件 | 通信效率取决于互联拓扑 | NVLink/PCIe、GPUDirect、RDMA |
| 任务调度 / 集群管理 | 多卡作业需要 Gang 与拓扑放置 | Gang scheduling、拓扑感知、容错 |
| 操作系统 | 并行与通信落到系统层 | 进程/线程、socket/RDMA、pinned memory |
| LLM 推理系统 | 训练产物供推理使用 | 模型权重、并行切分方式 |
| 性能预测 | 训练吞吐建模 | 通信/计算重叠、bubble、MFU |
