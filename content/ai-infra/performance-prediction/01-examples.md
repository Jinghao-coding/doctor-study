## 一句话结论

性能预测例子要说明预测目标是什么、输入特征是什么、结果如何服务调度或容量规划。

## 面试回答

**30 秒版：**

我用两个真实例子讲性能预测：推理侧预测输出 token 长度，用两阶段 LightGBM，特征是结构化加 MiniLM 语义降维，分类 AUC 0.96、回归 R² 0.78，推理约 10ms；训练侧预测作业执行时间，用 Random Forest，特征是硬件计数器加历史统计，MAPE 约 30%、R² 0.73，推理小于 1ms。关键是预测结果要服务调度和内存管理，而不只是离线分数。

**2 分钟版：**

这一节用推理和训练两个对照例子说明 ML-for-Systems 的预测落地。推理场景预测的是 LLM 输出 token 长度，因为输出长度直接决定 KV 缓存需求；用两阶段 LightGBM，特征来自 agent 角色、工作流位置等结构化信号加 MiniLM 编码再 PCA 降维的语义信号，分类 AUC 0.96、回归 R² 0.78，推理约 10ms，冷启动靠 per-role 回退到全局模型，更新靠 post-execution profiling 加 EWMA。训练场景预测的是作业执行时间，服务于调度排序和抢占决策；用 Random Forest，特征是 DCGM 硬件计数器加历史统计，MAPE 约 30%、R² 0.73，推理小于 1ms 以适配 50ms 调度预算，需要约 50 条历史样本才有效，靠周期再训练加 EMA 平滑维护。两个例子的共同点是：选轻量树模型保证低延迟和小样本可用，再把预测信号接到调度或内存决策上。面试里我会强调不要只讲模型精度，而要讲清预测如何被系统消费、误差如何被安全裕度和回退兜住。
