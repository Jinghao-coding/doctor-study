## GPU 集群管理在 AI Infra 中的定位

GPU 集群管理是把**调度理论和 K8s 能力组合成可运营的 GPU 平台**的那一层。它要解决多团队抢卡、训练作业全或无、跨机通信、长时间训练容错这些真实的生产问题。

面试考集群管理，本质是确认：你是否理解为什么通用 K8s 调度器不够用，以及 Volcano/Kueue 这类系统补齐了哪些能力。

<div class="card card-d">
<h3>一句话定位</h3>
<p>集群管理 = <strong>批调度（Gang） + 多租户配额 + 拓扑感知 + 容错弹性</strong>。它在 K8s 之上，把"裸 GPU 资源"变成"多团队共享、能跑大规模训练、能从故障恢复"的平台。</p>
</div>

## 与其他模块的关系

| 关联模块 | 关系 | 关键连接点 |
|---|---|---|
| Kubernetes 核心 | 集群管理扩展 K8s 调度 | Scheduler 扩展点、Device Plugin、CRD |
| 任务调度理论 | 落地公平与批调度算法 | DRF、Elastic Quota、Gang、Backfill |
| 分布式训练 | 为多卡训练提供 Gang 与容错 | 全或无调度、Checkpoint、弹性训练 |
| GPU 硬件 | 拓扑与通信决定放置 | NVLink/PCIe 拓扑、NCCL、NUMA 亲和 |
| 系统设计题 | 多租户调度是高频设计题 | 配额、借用、干扰感知合用 |

## 本模块包含哪些内容

| 板块 | 覆盖内容 | 典型面试问题 |
|---|---|---|
| 框架与多租户 | Volcano/YuniKorn/Kueue、配额、隔离、公平性 | Volcano 比默认调度器强在哪？多租户怎么做配额？ |
| 通信与容错 | GPU 拓扑、NCCL 通信、Checkpoint、弹性训练 | 训练作业挂了怎么恢复？怎么做拓扑感知放置？ |
| 面试 | 集群管理高频问题与回答要点 | 怎么设计一个多租户 GPU 集群？ |
