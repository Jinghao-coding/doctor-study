<div class="qa-q">Q: GPU 利用率为什么普遍很低？怎么提升？</div>
<div class="qa-a">
<p>原因：(1) <strong>碎片化</strong>——剩余 GPU 分散在不同节点，大任务放不进去。(2) <strong>I/O 瓶颈</strong>——数据加载阶段 GPU 空闲。(3) <strong>配额闲置</strong>——有配额但没任务。(4) <strong>通信开销</strong>——AllReduce 时 GPU 等待网络。</p>
<p>提升方法：(1) Bin Packing 减少碎片；(2) 弹性配额借用（DRA）解决配额闲置；(3) MPS 合用解决 I/O 阶段空闲；(4) 通信-计算重叠。</p>
</div>
</div>

<div class="qa" onclick="this.classList.toggle('open')">
<div class="qa-q">Q: 如何监控 GPU 集群？</div>
<div class="qa-a">
<p>三层监控：</p>
<ol>
<li><strong>硬件层</strong>：DCGM（Data Center GPU Manager）收集 GPU 温度、功耗、ECC 错误、SM 利用率、显存使用</li>
<li><strong>调度层</strong>：调度延迟、排队深度、配额使用率（QAD）、抢占频率</li>
<li><strong>任务层</strong>：训练 loss 曲线、吞吐（samples/s）、GPU 利用率、checkpoint 频率</li>
</ol>
<p>通常 DCGM → Prometheus → Grafana 的技术栈。</p>
</div>

<div class="qa-q">Q: 训练任务和推理任务的调度有什么区别？</div>
<div class="qa-a">
<table>
<tr><th>维度</th><th>训练</th><th>推理</th></tr>
<tr><td>时间尺度</td><td>小时到天</td><td>毫秒到秒</td></tr>
<tr><td>资源模式</td><td>独占整卡，Gang scheduling</td><td>可共享，弹性伸缩</td></tr>
<tr><td>失败代价</td><td>高（可能丢失小时级进度）</td><td>低（重试即可）</td></tr>
<tr><td>调度频率</td><td>低（每个任务调度一次）</td><td>高（每秒数千请求路由）</td></tr>
<tr><td>SLO 指标</td><td>JCT、公平性</td><td>TTFT、TPOT、P99 延迟</td></tr>
</table>
