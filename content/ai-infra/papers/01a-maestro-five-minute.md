<div class="qa-q" onclick="this.parentElement.classList.toggle('open')">Q: 请介绍一下利用 Agent 行为预测优化推理调度的工作。</div>
<div class="qa-a">
<p>这项工作研究多个 Agent 工作流共享 GPU 时，怎样减少长任务阻塞短任务，并降低多模型服务的显存浪费。比如旅行助手查航班时，可能只生成一小段工具参数；最后整理行程时，却要生成很长的回答。<strong>这些调用的时间和显存需求差别很大，只按到达顺序执行、按最大长度预留资源，容易既排长队又浪费显存。</strong></p>
<p>我们的做法是先估计调用成本，再据此安排工作流和资源。预测时结合输入语义、Agent 角色和工作流位置，先估计调用工具的概率，再把这个概率交给长度回归器，预测输出 token 数。这样能利用“生成工具参数”和“生成长回答”的行为差异。预测长度再换算成执行时间和 KV Cache 需求。</p>
<p><strong>排序看的是工作流预计还要多久完成。</strong>当前调用的时间来自预测，后续时间结合工作流位置和历史执行估计。在优先级条件相同的情况下，优先推进剩余时间短的工作流。交互任务与后台任务竞争时，可以让后台任务在完成当前调用后暂缓下一步，把执行机会让出来；等待过久的任务也会提高优先级。</p>
<p><strong>放置还要考虑模型是否就绪，以及腾空间会影响谁。</strong>先排除显存放不下的节点，再结合网络与显存匹配、排队和模型激活时间、回收后的恢复代价打分。某个节点计算更快，如果还要排很久或重新加载模型，也未必更合适。</p>
<p>节点运行时负责落实显存分配。近期要用的模型尽量留在 GPU，暂时不用的权重可以移到 CPU，更冷的再放到磁盘。KV Cache 通过 CUDA 虚拟内存管理按需映射物理页，避免一开始就占满最大预算；每次实际分配仍检查容量，并保留预测余量。调用结束后，用真实长度和用量校准后续估计。</p>
<p>高争用模拟中，相比 EDF，服务时限达成率提高 23.6 个百分点；另一组显存实验中，KV 预留的物理显存开销降低 67.2%。<strong>核心是把 Agent 的行为差异转成时间和显存估计，再让工作流排序、节点选择和实际资源管理共同使用这些信息。</strong></p>
 </div>

<h3>排序和放置使用不同的依据</h3>
<p><strong>工作流排序：</strong>预计剩余时间 = 当前阶段预计执行时间 + 后续工作流时间估计。后续项来自近期相似状态的执行记录中位数，状态包括角色、阶段模板、调用序号和工具意图等。工作流依赖仍需满足；预测工具参数的长度不能替代工具执行耗时。</p>
<p><strong>节点放置：</strong>先检查策略和显存可行性，再计算分数，选择最高分节点：</p>
<div class="formula">$$S(N,T)=A(N,T)-\lambda T_{ready}(N,T)-\mu C_{deg}(N,T)$$</div>
<ul>
<li>N 是候选节点，T 是当前模型调用。</li>
<li>A 是匹配分数，考虑网络距离和显存 best-fit；不是单纯空闲显存越多越好。</li>
<li>T_ready 是开始执行前的预计等待，由节点排队时间与模型激活时间组成。</li>
<li>C_deg 是腾出资源所需回收方案带来的恢复代价；影响活跃执行还会计入额外惩罚。</li>
<li>λ、μ 控制两类代价的权重。论文对指标做稳健归一化，时间项以毫秒报告，默认 λ = μ = 1。</li>
</ul>
<p>论文公式 (5) 是候选节点评分，公式 (7)–(8) 是工作流剩余时间估计；两者共同服务调度，但不能合并成一个声称全局最优的 cost。Algorithm 3 遍历可行节点并选最高分，节点资源协调的 Algorithm 2 按状态优先级贪心构造回收方案。</p>

<h3>普通抢占与内存压力处置要分开</h3>
<p>普通交互优先调度在两次模型调用之间切换，避免打断正在 decode 的调用；显存压力下的分级处置还可能涉及活跃 KV 换出或中止执行，这属于更高扰动的资源降级，需要计入恢复和中断代价。不能把阶段边界抢占说成任何情况下都不会中止活跃执行，也不能声称交互请求一定立即运行。</p>
<h3>实验数字的口径</h3>
<p>23.6 个百分点是高争用模拟中相对 EDF 的 SLO 达成率提升；67.2% 是显存实验中的 KV 预留 HBM 开销下降，不是总显存或每个请求实际 KV 数据量都下降相同比例。预测与后续服务实现的差异以两阶段预测实现章节的核对记录为准。</p>
